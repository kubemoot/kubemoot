{{- $name := include "kubemoot-vllm.fullname" . -}}
kubemoot-vllm is installing {{ len $servers }} vLLM server(s) behind the Service {{ $name }} in the namespace {{ .Release.Namespace }}.

The first start downloads the weights and compiles each model, which takes minutes. Watch it with:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ $name }} -f

Then tell Kubemoot about it. Create this ModelServer (change the namespace to the one
Kubemoot's operator runs in). The operator finds the servers from the Service's ports and
reads each model's parameters and capabilities from this release's values, which the chart
publishes on the Service (the kubemoot.ai/models annotation):

---
apiVersion: kubemoot.ai/v1alpha1
kind: ModelServer
metadata:
  name: {{ $name }}
  namespace: kubemoot
spec:
  type: vllm
  sleepLevel: {{ int .Values.sleepLevel }}
  serviceRef:
    name: {{ $name }}
    namespace: {{ .Release.Namespace }}

Every model this release serves joins the cluster's model catalog on its own; a Model object
is not needed. Models without a parameters value in this release's values have no size
class:
{{ range $s := $servers }}
  {{ $s.name }}: {{ if $s.parameters }}{{ $s.parameters }} parameters{{ else }}no parameters declared{{ end }}{{ if $s.capabilities }}, {{ join ", " $s.capabilities }}{{ end }}
{{- end }}

To add labels of your own to a model (data residency, license) or to keep one out of the
catalog, create a Model in Kubemoot's namespace with spec.model set to the served name and
spec.serverRef set to {{ $name }}.
