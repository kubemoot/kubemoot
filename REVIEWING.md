# Reviewing Pull Requests

Guidelines for reviewing contributions to Kubemoot.

- **Tests ship with code** — no change merges without tests for the behavior it
  changes (see the per-component policy in the repo).
- **GitOps discipline** — versions come from git tags; never hand-edit versions in
  manifests.
- **Small, focused PRs** review faster. Prefer one concern per PR.
- A maintainer approval is required to merge. Be kind and specific.

_Reviewer expectations will expand as the contributor base grows._
